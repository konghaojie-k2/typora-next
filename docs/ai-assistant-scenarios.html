    ⚖️ 利弊分析

    ✅ 值得做

    • PageIndex 思路简单：利用现有标题结构，无需向量数据库
    • 定位 + 总结双功能：不只是找到，还要理解
    • 代码解释集成在应用内，不用切换窗口
    • 差异化功能：VS Code/Obsidian 没有这个能力

    ❌ 需考虑

    • 需要 LLM API 调用（依赖网络 + 成本）
    • PageIndex 只适合有标题结构的文档，扁平文档效果差
    • 用户是否真的会高频使用？（可能只是看着酷）
    • 实现成本：~2-3 天开发 + API 费用
    建议：先做 MVP 版本（只实现场景 A：章节定位），验证用户使用频率后再扩展场景 B/C。

    如果发现用户很少用，可以降级为"智能搜索"（纯本地，无 LLM，只是标题匹配）。
